# 跨镜道路推测路径

模块四后端读取现有真实校园道路、边界、建筑、水面，不改写模块一空间文件、业务绑定或跨镜原始结果。

同一匿名 Global ID 的相邻摄像头节点，经空间检查获得道路接入点，再按路网最短距离推算路径。接入点是几何推算，未经过入口现场核验；摄像头仍为原有示范布点。建筑内锚点到道路的接入线不绘制。道路路径不代表连续 GPS，也不代表算法还原了人员实际步行路线。

禁止通行道路不参与；非桥梁道路的水面部分、建筑内部部分剔除，保留其余有效路段。按道路层级、桥梁和隧道标签区分交叉；未连接的道路不补造连线。摄像头接入超过120米、接入线经过其他建筑/水面、位置缺失或道路不连通时，仅保留节点或其他有效路段，明确提示待确认。

## 返回字段

- `nodes`、原始像素轨迹、Global/Local ID、评分、时间：保留。
- `upstream_segments`：保留上游原始连线。
- `segments`：仅包含道路推测路段；空数组表示不画直线。
- `route_legs`：逐段状态、道路接入位置、距离、时间核验提示。
- `route_status`：`ROUTED` 全部可推算；`PARTIAL` 部分可推算；`NODES_ONLY` 仅节点。
- `route_distance_m`：已推算路段的距离之和，部分缺失时不是全程距离。

时间核验使用原始时间；间隔不为正或道路距离对应速度超过2.5米/秒，提示待核验，不篡改上游综合分数。

GIS、2.5D、3D复用同一份后端道路几何，并显示方向箭头。分类勾选按匿名对象增减；同一对象几何更新时单独更新地图图层。

DEMO接口200：25个对象、8个摄像头保留；4个对象全部可推算、13个部分可推算、8个仅节点，共17个道路路段。CAM01、CAM02暂未找到满足当前约束的安全接入点，不能宣称所有路线已经完成。

后端30项测试通过；前端13项既有浏览器回归通过；生产构建通过。道路缺失与入口实测核验需要后续补充有来源的空间资料，不能靠演示造路。

## 接入修正后的复测

教学楼一、二的具名轮廓完整包含在 `HBUE-B047` 建筑群外轮廓内。此前接入检查错误地把该外轮廓视为另一栋阻挡建筑。现仅在摄像头属于具名建筑、且外轮廓覆盖其面积至少99.9%并包含摄像头时，将两者作为同一物理建筑锚点验证接入；不删除外轮廓，不改变道路障碍，不绘制建筑内部接入线。

运行接口复测：DEMO保留25个对象，25条均可推算，共46个道路路段；LIVE实际返回1个对象，生成1个道路路段。全部46个示范道路路段通过现有路网覆盖、校园范围及建筑内部避让检查。摄像头部署仍为示范、道路推测仍非人员实际GPS路径，入口位置仍需现场核验。

新增“嵌套建筑群不误阻挡”和“其他相邻建筑继续阻挡”测试，后端32项测试通过。
