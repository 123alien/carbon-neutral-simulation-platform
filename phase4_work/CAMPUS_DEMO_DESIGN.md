# 智慧低碳示范校园设计与数据规则

## 1. 校园总体设定

- 校园业务编码：`CAMPUS-DEMO-001`
- 系统归属：复用现有 `Site(site_type=CAMPUS)`，不建立第二套校园主数据。
- 校园名称：智慧低碳示范校园。
- 建筑类型：教学楼、实验楼、行政楼、图书馆、学生宿舍、食堂及综合服务楼。
- 时区：`Asia/Shanghai`；数据库时间按 UTC 存储，接口使用带时区的 ISO 8601。
- 数据性质：所有生成记录统一标记 `DEMO_SIMULATION / 示范仿真数据`。
- 隐私边界：本阶段不生成视频、人脸、姓名、车牌或跨镜追踪结果。

## 2. 建筑及区域编码表

| 建筑 | building_id | 类型 | 建筑面积 | 楼层 | 主要业务 |
|---|---|---:|---:|---:|---|
| 教学楼 | CAMPUS-DEMO-001-BLD-TCH | 教学 | 16,800 m² | 6 | 课堂教学、自习 |
| 实验楼 | CAMPUS-DEMO-001-BLD-LAB | 实验 | 12,800 m² | 5 | 实验、科研与设备运行 |
| 行政楼 | CAMPUS-DEMO-001-BLD-ADM | 办公 | 8,600 m² | 6 | 行政办公、会议 |
| 图书馆 | CAMPUS-DEMO-001-BLD-LIB | 图书馆 | 14,200 m² | 7 | 阅览、自习、数字资源 |
| 学生宿舍 | CAMPUS-DEMO-001-BLD-DOR | 住宿 | 22,600 m² | 10 | 学生住宿、生活用水 |
| 食堂及综合服务楼 | CAMPUS-DEMO-001-BLD-DIN | 餐饮服务 | 9,800 m² | 4 | 早、中、晚餐及综合服务 |

编码规则：

- `floor_id = {building_id}-F{floor_number:02d}`
- `area_id = {floor_id}-A{area_number:02d}`
- 每层首版设置主要使用区、公共区域和机电设备区。
- 名称可修改，业务编码不随名称变化，已使用编码不重复分配。

## 3. 能源系统和设备配置

校园级建立供配电、给水、食堂燃气、屋顶光伏、小型风电、储能、充电设施、空调和照明系统。每栋建筑建立用电、用水、空调和照明设备及计量点；食堂额外建立天然气设备和计量点。光伏、风电、储能和充电桩作为校园公共能源设施关联室外 `area_id`。

## 4. 各建筑典型日业务规律

- 教学楼：工作日8:00–12:00、14:00–18:00出现课堂高负荷，周末显著降低。
- 实验楼：工作日8:00–21:00保持较高负荷，设备工艺负荷高于普通教学空间。
- 行政楼：工作日8:00–18:00集中使用，夜间和周末仅保留基础负荷。
- 图书馆：8:00–22:00持续开放，周末仍保持较高使用率。
- 学生宿舍：6:00–9:00、18:00–24:00用电和用水升高，夜间保留持续负荷。
- 食堂：7:00、12:00、18:00形成三次就餐峰值，用电、用水和天然气同步变化。

## 5. 数据生成规则

- 不使用随机数；规则由时间、工作日、建筑类型、占用率、季节和气象函数共同驱动。
- 空调：根据室外温度相对24℃和12℃的偏差，结合建筑占用率计算冷热负荷。
- 光伏：夜间为0，白天按太阳高度的日内曲线、季节和确定性云量系数计算。
- 风电：风速由日尺度与小时尺度连续周期函数生成，功率按切入、额定和切出风速曲线计算。
- 储能：1:00–6:00充电，17:00–21:00放电；充放电效率0.95，SOC约束15%–90%，同时段不允许同时充放电。
- 充电桩：工作日到校和离校时段高于日间平峰，周末显著降低。
- 所有记录经现有数据源、字段映射、L1/L2/L3校验和 `DeviceMetric` 入库链处理。

## 6. 与现有园区数据的映射

| 校园概念 | 现有对象 | 存储方式 |
|---|---|---|
| campus_id | Site.code / Site.metadata_json | 业务编码，系统主键仍为 site.id |
| building_id | Building.code / metadata_json | 与 site_id 联合唯一 |
| floor_id | Building.metadata_json.floors | 首版使用结构化 JSON |
| area_id | Building/Device/MeteringPoint.metadata_json | 连接空间、设备与计量点 |
| 能源系统 | EnergySystem | 复用现有系统类型 |
| 设备与计量 | Device / MeteringPoint | 复用现有关联和园区隔离 |
| 时序事实 | DeviceMetric | 复用现有单位和L1/L2/L3校验 |

## 7. 后续跨镜追踪统一字段规范

必填主键：`campus_id`、`building_id`、`floor_id`、`area_id`、`timestamp`。后续行为事件接口建议同时使用 `event_id`、`object_id`、`object_type`、`source_device_id`、`camera_id`、`event_type`、`confidence`、`coordinate_system`、`position_x/y/z`、`data_class`。

`object_id` 必须是脱敏的临时标识，不使用姓名、证件号、人脸特征或未脱敏车牌。跨镜服务只向碳中和平台输出结构化事件；碳中和平台负责将事件转换为可审计的活动数据，不直接把人数或车辆事件当作碳排放。

## 8. 执行与测试

```powershell
$env:DEMO_MODE='1'
$env:DATABASE_URL=$env:DEV_DATABASE_URL
python scripts/seed_campus_demo.py --hours 720
pytest tests/test_campus_demo_rules.py -q
```

`--hours 720` 生成30天试用数据；需覆2024闰年全年小时数据时使用 `--hours 8784`。脚本幂等：检测到已有校园事实时不重复写入。
