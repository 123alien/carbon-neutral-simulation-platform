# 真实数据接入清单

> 本文件只记录真实数据的取得、授权、质量和导入状态，不保存密码、Token、个人敏感信息或未经授权的原始数据。所有未核实项目均标记为“待确认”，禁止使用演示数据补齐缺口。

## 1. 第一批验收目标

第一批先完成：

`园区/企业基础信息 → 建筑/设备台账 → 用能数据 → 气象 → 电价 → 排放因子`

满足后应能够真实跑通：

`/data → /carbon → /simulation → /dashboard`

## 4. 真实用能数据专项检查

### 时间与完整性

- [ ] 已明确原始时区，统一存储为 UTC，页面按 IANA 时区展示。
- [ ] 已明确读数含义：瞬时功率 kW、区间电量 kWh 或累计表底。
- [ ] 已明确采样粒度：15 分钟、小时、日或月。
- [ ] 已检查重复时间戳。
- [ ] 已检查缺失区间和不规则间隔。
- [ ] 已检查未来时间戳和越界值。
- [ ] 2024 完整小时数据按每个计量点应为 8,784 条。
- [ ] 总表与分表差异已分析，未通过修改数据强行平衡。

### 单位与计量关系

- [ ] 每条数据可以追溯到唯一计量点编码。
- [ ] 计量点已关联真实 Building、Device 或 EnergySystem。
- [ ] W/kW/MW、Wh/kWh/MWh 已区分，不混淆功率和电量。
- [ ] 天然气、热力和燃油单位已记录原始口径和换算依据。
- [ ] 原始文件保留不变，清洗后文件单独版本化。

## 5. 气象、电价和排放因子检查

### 气象

- [ ] 数据源名称、站点坐标和授权方式已记录。
- [ ] 夜间 GHI/DNI/DHI 合理，辐照值非负。
- [ ] humidity 为 0–100%，温度和风速范围合理。
- [ ] 气象时间范围覆盖需要仿真的用能时间范围。

### 电价

- [ ] 已确认峰、平、谷时段及法定节假日规则。
- [ ] 已确认是否含税、基本电费、需量电费和力调费用。
- [ ] 上网电价与购电价分开记录。
- [ ] 每套规则具有生效和失效日期。

### 排放因子

- [ ] 因子来自正式可追溯来源。
- [ ] 已记录地区、年份、版本、单位和标准依据。
- [ ] 动态因子缺失时，仅使用已确认的固定年度因子 fallback。
- [ ] 前端不得把 fallback 标为实时动态数据。

## 6. 数据安全与授权

- [ ] 数据提供部门和负责人已确认。
- [ ] 已确认数据使用授权、保密等级和保留期限。
- [ ] 涉及人员、车辆或充电订单的数据已去标识化。
- [ ] MQTT、REST API 和第三方系统凭证不写入本文档。
- [ ] 原始数据存储位置有访问控制和备份。
- [ ] 正式数据只进入 PostgreSQL 环境，不进入 E2E 或 validation fixture 数据库。

## 8. 分阶段完成条件

### 第一阶段：数据接入

- 基础对象、计量关系和真实来源可追溯。
- 正常文件 Preview/Confirm 成功；错误文件不允许 Confirm。
- 数据质量页明确显示完整、缺失、异常、重复和最近时间。

### 第二阶段：碳核算与仿真

- Scope 2 使用正式电网因子。
- 实际存在 Scope 1 能源时才纳入核算。
- 小时仿真使用真实负荷；PV/WIND/HVAC 仅在气象数据满足要求时启用。
- 缺失数据显式标记，不静默补值。

### 第三阶段：扩展业务

- 真实存在 PV、储能、充电桩和绿电合同后再建立对应设备或合同。
- 碳市场、CCER、绿证只在企业适用且来源可靠时接入。
- 推荐、场景、风险和报告必须引用已冻结的真实输入快照。
