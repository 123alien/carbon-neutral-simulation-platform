# 平台信息架构

## 一级菜单

1. 综合首页
2. 园区管理
3. 数据接入
4. 碳核算
5. 3D全景
6. 碳中和仿真
7. 碳市场
8. 报告中心

系统运行、模型验证、数据接入技术配置等仍保留路由和能力，但不作为普通业务用户的一级导航。

## 主业务流程

园区管理 → 数据接入 → 碳核算 → 碳中和仿真 → 报告中心。

园区管理是主数据入口，园区、建筑、能源系统、设备和计量点均在该模块内创建与维护。数据接入不再承担“初始化平台”职责，只针对已经存在的园区对象执行：接入对象 → 数据源 → 数据采集/导入 → 数据质量结果。

3D全景是当前园区数据的独立空间可视化；碳市场是独立研究模块，同时可为仿真情景参数提供参考。

`/3d` 使用独立全屏布局，不嵌入普通业务侧栏与工作页签。大屏以当前园区为唯一上下文，统一读取园区概览、建筑碳排、设备遥测及同一仿真任务的小时能源结果；空间对象可下钻，并可跳回碳核算和碳中和仿真。

## 碳中和仿真工作台

当前基准状态 → 目标与约束 → 路径推荐 → 全过程仿真 → 场景结果对比 → 情景参数调整 → 综合分析。

工作台复用现有推荐、小时仿真、不可变场景版本、批量仿真、比较和风险接口。历史 `/simulation`、`/recommendations`、`/scenarios`、`/risks` 路由保留，既有深链接不失效。

## 显性与隐性能力

业务用户直接操作园区对象、数据源、碳核算、目标、路径、场景、市场和报告。安全传输、字段映射、单位换算、自动清洗、三级校验、排放因子调用、能源平衡和设备模型作为流程内部能力呈现状态和结果，不拆分为一级菜单。

## 数据范围

综合首页、园区管理、数据接入、碳核算、3D全景和新仿真工作台均由全局当前园区上下文驱动。公开验证园区继续通过 `scope=VALIDATION` 进入模型验证中心，不出现在正式业务园区选择器中。碳市场趋势为公共市场数据；园区情景和成本评估仍绑定当前园区选择的场景版本及仿真任务。

## 园区管理与数据接入边界

- `/park`：园区及园区内部对象的新增、查看和配置，不跳转数据接入。
- `/data`：已有对象的数据来源、采集/导入和质量结果，不创建园区主数据。
- 历史 `/data?setup=1`：仅作兼容重定向至 `/park?create=site`，不再渲染旧初始化向导。
