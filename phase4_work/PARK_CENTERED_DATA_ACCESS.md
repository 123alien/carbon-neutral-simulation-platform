# 园区中心化数据接入

统一流程：创建园区 → 创建建筑 → 创建设备 → 创建计量点 → 配置数据源 → 数据采集或导入 → 三级清洗校验 → 动态碳核算 → 基准场景 → 低碳路径推荐 → 多场景仿真 → 报告。

园区是业务页面的数据上下文；建筑、能源系统、设备和计量点是园区对象；数据源只负责把外部数据送入已确定的对象。平台不提供“从数据集创建园区”的旁路。

## 数据范围

- `GET /api/sites?scope=BUSINESS`：正式业务园区。
- `GET /api/sites?scope=VALIDATION`：公开模型验证园区。
- `GET /api/sites?scope=ALL`：系统管理兼容视图；默认 `ALL` 保持原接口兼容。
- 正式前端园区上下文固定使用 `BUSINESS`。
- 数据接入工作台使用 `enterprise_id + site_id` 查询数据源和质量汇总。

验证分类读取园区 `metadata_json.data_class`：`REAL_PUBLIC`、`REAL_PUBLIC_OFFICIAL`，或 `business_class=MODEL_VALIDATION`。历史记录不删除，只从正式园区选择器中排除并归入模型验证中心。

## 数据源关联

数据源可关联园区，并可进一步关联建筑、设备、计量点。后端校验关联对象必须属于同一企业和园区，跨园区绑定会被拒绝。

文件数据性质包括 `MEASURED`（实测数据）、`SIMULATED`（仿真数据）、`HISTORICAL`（历史数据）。旧数据源关联字段允许为空以保证历史记录可读；新前端流程要求选择园区。三级质量校验和既有文件、接口、物联网、第三方、人工录入能力保持不变。
